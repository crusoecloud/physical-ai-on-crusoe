# Troubleshooting — full decision table

Part of the run-osmo-workload skill. Read SKILL.md first. SKILL.md keeps the
high-frequency runtime rows inline; this is the complete table, including the
install-side rows that are the deploy skill's territory (noted per row).

| Symptom | Cause | Action |
|---|---|---|
| Stage 1 fails at `uv pip install -e .` | transient PyPI/GitHub network | restart once; twice → report |
| Stage 1 sanity gate fails (`total_episodes` mismatch) | converter layout drift (upstream changed) | read `meta/info.json` from the log dump; pin the converter commit that matches; never hand-edit metadata |
| Stage 1 HF download 401 | wrong/expired token (the dataset itself is ungated, apache-2.0) | user re-runs `osmo credential set hf-token`; never the agent |
| Stage 2a task OOM at generation | offload/downcast flags dropped by an edit | confirm `guardrail_config.enabled = False`, `prompt_refiner_config.enabled = False`, `offload_text_encoder=False`, `downcast_text_encoder=True` in `/tmp/augment_one.py` (the encoder stays resident bf16 — `offload_text_encoder=True` is broken in the pinned repo: device mismatch); restart |
| Stage 2a `aligned to` line missing or count wrong | trim pass failed (ffmpeg missing in container) | the container carries ffmpeg; if `apt-get install ffmpeg` failed (network), restart |
| Stage 2a all tasks PENDING forever | `l40s` pool missing or saturated | Phase 0b's node gate; `kubectl get nodes -l crusoe.ai/nodepool.name=l40s` |
| Stage 2b assertion `no augmented clips` | wrong `stage2a_id` or prefix | re-check the ID and the bucket prefix; resubmit |
| Stage 2b assertion `episode does not start at 0` | source dataset's timestamps not episode-relative | the timestamp rewrite is wrong for that dataset: stop, report (merge-augmented.md) |
| Stage 3 fails at flash-attn install | pip resolution drift at the pinned commit | restart once (pip cache); persistent → report; **never bump the pins** (they are the verified set) |
| Stage 3 OOM mid-training | batch too large for the config | resubmit with `--set batch_size=2` (global 16); do not raise `max_steps` to compensate |
| Stage 3 stuck PENDING | `h100` pool busy | `osmo workflow list --status RUNNING`; queue_timeout 4h then reschedules; or ask the user whether to wait |
| Workflow hangs RUNNING but task finished | install regression (`service_base_url`/CA) | send the user to skills/deploy-osmo-crusoe/references/osmo-install.md Phase 7/8 checks — this skill does not fix installs *(install-side: deploy skill's territory)* |
| `osmo login` fails TLS verify (self-signed) | gateway cert not in trust store | `SSL_CERT_FILE`/`REQUESTS_CA_BUNDLE` = a bundle with BOTH the gateway cert and the Keycloak cert (Phase 1b); never disable verification |
| `osmo login --method code` fails `HTTP 405` at the device start | Keycloak 26 moved the device endpoint | `services.service.auth.device_endpoint` = `.../realms/osmo/protocol/openid-connect/auth/device` (not `/device`); helm upgrade + restart `osmo-service` *(install-side: deploy skill's skills/deploy-osmo-crusoe/references/keycloak.md owns the values)* |
| `osmo` calls after login fail `403 Audiences in Jwt are not allowed` | the device-flow id_token carries `aud=osmo-device` | add a third JWT provider (`audience: osmo-device`) to `gateway.envoy.jwt.providers` + restart Envoy *(install-side: deploy skill's skills/deploy-osmo-crusoe/references/keycloak.md owns the values)* |
| Submit fails `Unable to authenticate for pulling image nvcr.io/...` | OSMO's server-side registry validation rejects public nvcr.io images without an NGC credential | either register an NGC REGISTRY credential (`osmo credential set nvcr --type REGISTRY --payload registry=nvcr.io username='$oauthtoken' auth=<NGC key>`) or set `services.configs.workflow.credential_config.disable_registry_validation: ["nvcr.io"]` + service upgrade/restart. CRITICAL distinction: disable_registry_validation only fixes the SUBMIT-side check; the RUNTIME pull by the node's containerd still fails with `insufficient_scope` if NVIDIA has gated the image (cosmos-predict2-container is behind NGC auth - a plain k8s pod with the same image fails identically). For the runtime pull, register the NGC REGISTRY credential and add it to the task's `credentials:` block; NVIDIA has been retroactively gating Cosmos containers, so an image that pulled anonymously last month may not today. |
| Two `--set a=x --set b=y` flags: only the LAST one applies (the first's values are silently dropped — the failure signature is `'stage1_id' is undefined` at submit) | OSMO's submit parser takes one value-set per `--set` occurrence and the later flag replaces the earlier | put all overrides after ONE `--set` separated by spaces (`--set a=x b=y`), or mix `--set-string`/`--set` flags; verify the rendered spec before proceeding *(encoded in scripts/submit_stage.sh, which refuses multiple `--set`)* |
| `--set storage_url=...` SILENTLY does not override (the render keeps the placeholder) | OSMO's `--set` string handling drops non-numeric values with `://` | ALWAYS override with `--set-string storage_url=...`; verify the rendered spec (`osmo workflow spec <id> \| grep -E 'storage_url:\|url:'` — must show the real bucket and no `osmo-bucket-placeholder`) after submitting anything with a storage_url override *(encoded in scripts/submit_stage.sh)* |
| Submit fails `NoCredentialsError` at `Validating WRITE access` | no user-level DATA credential registered | `osmo credential set <name> --type DATA` with the bucket's key/endpoint/region/override_url/addressing_style (Phase 1f); the service-side config does not cover submit validation |
| Submit fails `Multiple tasks/groups have the same name` | OSMO treats group name == task name as a collision | rename the task (task names differ from their group's) |
| Stage 1 fails building `evdev` from source | python-slim image lacks build toolchain | the workflow's apt line carries build-essential/python3-dev/linux-libc-dev (present in the shipped YAML); if you base a variant on a different image, include them |
